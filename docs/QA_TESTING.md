# Автотесты каталога

Тесты написаны на Playwright и лежат в `e2e/catalog/`. Они проверяют поведение сайта глазами пользователя
(роли, подписи, тексты), а не внутреннюю реализацию. В продакшн-коде для тестов добавлены только
`data-testid="product-modal"` (окно товара), `data-testid="contact-menu"` (меню связи) и
`data-testid="mobile-contact-bar"` (нижняя панель на телефоне).

## Запуск

```bash
npx playwright test --project=catalog                # весь каталог (153 теста, около минуты)
npx playwright test --project=catalog -g "поиск"     # по названию теста
npx playwright test --project=catalog --ui           # с интерфейсом
```

Dev-сервер Playwright поднимает сам (`http://127.0.0.1:5173`). Если браузер Chromium для Playwright не установлен,
можно запускать в Microsoft Edge:

```powershell
$env:PW_CHANNEL='msedge'; npx playwright test --project=catalog
```

Проекты в `playwright.config.ts`: `catalog` (этот набор), `chromium` (общие тесты, например `e2e/smoke.spec.ts`),
`chromium-auth` (тесты входа из старого проекта, к каталогу не относятся).

## Файлы

| Файл | Что проверяет |
|---|---|
| `helpers.ts` | общие функции: чтение карточек, фильтры, ожидание конца прокрутки, сбор ошибок консоли |
| `catalog-data.spec.ts` | данные 51 товара: уникальные артикулы, цены в разумных пределах, счётчик, нет ошибок в консоли |
| `catalog-filters.spec.ts` | категории, сортировка по цене, фильтры «Материал» и «Цвет», их сочетания, поведение выпадающих списков |
| `catalog-search.spec.ts` | поиск: регистр, пробелы, дефисы, ё/е, Metta/Метта, пустой результат, очистка, сочетание с фильтрами |
| `product-modal.spec.ts` | окно «Подробнее»: данные, закрытие, Esc, диалог и фокус, блокировка прокрутки, двойной клик, телефон |
| `contacts.spec.ts` | телефон, Telegram, WhatsApp, почта, меню связи в шапке, на первом экране, плавающая кнопка, мобильная панель |
| `navigation.spec.ts` | якоря, шапка, «Наверх», прямые переходы по URL, неизвестные адреса, политика конфиденциальности, мобильное меню |
| `responsive-a11y.spec.ts` | экраны 320–1440 px, горизонтальное переполнение, нижняя панель, `aria-*`, заголовок, описание, иконка вкладки |
| `resilience.spec.ts` | сбои картинок и сети, медленные шрифты |
| `unexpected-order.spec.ts` | действия в неожиданном порядке: смена размера окна при открытом меню, поворот телефона, ручная смена хэша, «Назад», WhatsApp в новой вкладке, быстрое открытие и закрытие окна |

Тесты, которые проверяют ранее найденные дефекты, помечены `[BUG?]` в названии. Теперь они проходят и защищают от возврата ошибок.

| Esc не закрывал выпадающие списки фильтров | закрывает |
| Окно товара: нет Esc, роли диалога, ловушки фокуса; страница под ним прокручивалась; двойной клик закрывал окно | исправлено |

## Что не покрыто

- Переключение фото в галерее: у всех товаров по одной картинке.
- Открытие приложений по `tg://` — проверяется только содержимое ссылки.
- Собранная версия (`vite build` + `preview`) и браузеры Firefox/WebKit — прогон только на Chromium/Edge.
- Латинская «A» вместо кириллической «А» в поиске даёт пустой результат — не проверяется и не исправлялось.
- API, авторизации и форм в каталоге нет, поэтому тестов на них нет.

## Как добавлять тесты

1. Новый товар или фильтр — достаточно изменить `src/data/products.ts`: тесты данных и доступности через фильтры подхватят его сами.
2. Новый тест кладите в подходящий `*.spec.ts`, каждому тесту нужно самому готовить состояние (`openCatalog(page)`).
3. Ожидайте конкретное состояние (`expect(...).toBeVisible()`, `expect.poll`), а не `waitForTimeout`.
4. Не ослабляйте проверку, чтобы тест прошёл: сначала выясните, что сломано — сайт или тест.
